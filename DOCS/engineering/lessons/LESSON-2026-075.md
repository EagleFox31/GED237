# LESSON-2026-075 — `git push -u` depuis un worktree créé sur `origin/main` : le push a visé `main`

- **Date :** 2026-11-19
- **Catégorie :** process / git
- **Statut :** resolved (règle de push par refspec explicite)
- **Liens :** PR #467 (`ci/lessons-register-frozen`), ruleset GitHub 26190959 sur `main`

**Contexte** — Une branche de travail est créée dans un worktree séparé par `git worktree add -b ci/lessons-register-frozen <chemin> origin/main`, puis poussée par `git push -u origin ci/lessons-register-frozen`.

**Échec / near miss** — Git a répondu `ci/lessons-register-frozen -> main (non-fast-forward)` : le push visait `main`. Ce push direct était refusé dans tous les cas : `main` est protégé par le ruleset 26190959 (passage par PR obligatoire, sans contournement). Le message affiché venait seulement de ce que `main` avait avancé entre-temps (103ce48b). `main` n'a pas bougé ; la branche a ensuite été poussée sous son nom.

**Cause racine** — `worktree add -b X origin/main` règle `origin/main` comme branche suivie de `X`. Quand la destination est omise, `git push origin X` peut la prendre dans cette configuration de suivi (selon `push.default`), donc `main`.

**Classification** — Erreur de procédure ; garde-fou serveur présent (ruleset), garde-fou local absent.

**Résolution** — Push refait avec une destination explicite : `git push origin HEAD:refs/heads/ci/lessons-register-frozen`. Rien n'a été écrit sur `main`.

**Prévention** — Le ruleset protège déjà `main` côté serveur ; cette leçon ajoute le garde-fou local. Depuis un worktree, toujours pousser avec une destination explicite (`git push origin HEAD:refs/heads/<branche>`), et créer les branches de worktree avec `--no-track` (`git worktree add --no-track -b <branche> <chemin> origin/main`). Contrôle vérifiable : avant un premier push, `git rev-parse --abbrev-ref @{upstream}` ne doit pas répondre `origin/main`. Garde existante : ruleset 26190959 (PR, contrôles requis, ni suppression ni push forcé sur `main`).

**Leçon généralisée** — Ne jamais laisser Git déduire la destination d'un push : une branche créée depuis la branche par défaut en hérite le suivi, et une commande « habituelle » peut viser la branche protégée.
