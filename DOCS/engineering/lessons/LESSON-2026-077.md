# LESSON-2026-077 — KVM sous Docker Desktop : module non chargé, chemins réécrits par Git Bash, commande réinterprétée par wsl.exe

- **Date :** 2026-11-19
- **Catégorie :** tooling / environnement
- **Statut :** resolved (`scripts/lab/kvm_prereq.sh`, testé : vérification, déchargement, rechargement, relance sans effet)
- **Liens :** `scripts/lab/kvm_prereq.sh` (branche `feat/lab-kvm-prereq`), image de poste Windows conteneurisé (README de l'image, section KVM)

**Contexte** — Préparation du lab multi-postes : un poste Windows doit tourner dans un conteneur, ce qui exige `/dev/kvm` à l'intérieur.

**Échec / near miss** — Trois diagnostics faux à la suite :
1. conclusion « Windows impossible en conteneur », sans recherche ;
2. `docker run --device /dev/kvm` refusé avec « device "C" » ;
3. premier chargement du module en échec, « Module  not found » (nom vide).

**Cause racine** —
1. Sous Docker Desktop, KVM est compilé en module (`CONFIG_KVM=m`) dans le noyau WSL partagé, mais il n'est pas chargé. Le charger depuis une distribution WSL qui possède `/lib/modules` (Ubuntu) le rend visible des conteneurs.
2. Git Bash réécrit tout argument qui ressemble à un chemin POSIX.
3. `wsl.exe -- cmd` repasse la commande dans le shell de connexion de la distribution, qui développe `$m` avant que `sh -c` ne s'exécute.

**Résolution** — `scripts/lab/kvm_prereq.sh` :
- exporte `MSYS_NO_PATHCONV=1` ;
- appelle `wsl.exe -e`, qui exécute sans shell intermédiaire ;
- vérifie le résultat avec une sonde non privilégiée ;
- ne fait rien si KVM est déjà visible.

**Prévention** —
- Le script est le seul point d'entrée du prérequis KVM. Sa sonde finale échoue si `/dev/kvm` reste invisible.
- Toute commande Docker lancée depuis Git Bash avec un chemin Linux est préfixée par `MSYS_NO_PATHCONV=1`.
- Tout script qui passe une commande à `wsl.exe` utilise `-e`.

**Leçon généralisée** — Avant d'affirmer qu'une capacité est impossible, chercher l'existant et tester sur la machine cible. Quand une commande traverse plusieurs couches (Git Bash, wsl.exe, sh), vérifier ce que chaque couche réinterprète.
